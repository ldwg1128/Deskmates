# 행동·전환 분석과 보존 범위

원본 기준 커밋: `d892590`. 자동 생성한 파일·좌표·FPS·해시 목록은 [inventory.md](generated/inventory.md)와 [inventory.json](generated/inventory.json)을 참조한다. 카탈로그에는 현재 15개 행동 리소스와 19개 게임 상태/바인딩이 있다. 먹기와 물리 동작은 여러 상태가 한 이미지 리소스를 공유한다. 이미지 누락으로 실행 불가능한 기존 행동은 없다.

## 기존 이미지 사용

기본 시트는 1536×2288, 셀 192×208이며 위 9행은 대기·양방향 걷기·인사·점프·고개 숙이기·수줍음·생각·고개 기울이기, 아래 2행은 위쪽에서 시계 방향인 시선 16개다. 제니스는 셀 x=32, 폭128, 기준 신체 높이198을 사용한다. 리베르타는 x=16, 폭160, 기준167을 사용한다.

리베르타의 기본 시트 걷기 1·2행은 보존하지만 실제 표시는 motion 시트의 8~15번 수평 측면 포즈로 대체한다. 공통 자르기 `(96,0,384,512)`, 바닥497, 대기 자세와 비교한 공통 배율을 유지하고 왼쪽은 반전한다. motion 23번은 표시 동작이 아니라 서 있는 자세의 배율 기준이다. motion의 0~7·17번은 현재 경로에서 표시하지 않는다.

제니스 motion은 3×2/512×512 셀의 0~5번, 리베르타는 4×6/512×512 셀의 16·18·19·20·21·22번을 사용한다. 알파32 이상 경계로 자르되 잘라낸 내부의 희미한 픽셀을 임의 수정하지 않는다. 제니스는 서 있는 신체 높이462 기준으로 모든 물리 포즈에 같은 배율을 쓴다.

코너 점프는 캐릭터별 1254×1254의 2×2 셀, 각 알파 경계로 자르고 4번째 포즈 높이를 공통 배율 기준으로 삼는다. 먹기·배고픔·거절도 2×2지만 알파32 미만을 지운 후 Qt 마스크의 네 셀 합집합을 공통 영역으로 자른다. 일부 원본은 홀수 높이여서 마지막 남는 행을 기존처럼 사용하지 않는다. 먹기 계열은 대기 자세의 양발 중심과 바닥선에 정수 오프셋으로 맞춘다. 원본 PNG 자체는 변경하지 않는다.

`assets/spritesheet.png`와 `drag-landing.png`, `drag-landing-v2.png`, `drag-landing-v3.png`는 현재 사용하지 않으며 삭제하지 않는다. `bread.png`는 캐릭터와 독립적인 공통 빵이다. 기존 파일명과 경로는 JSON만 참조하므로 이전 산출물을 그대로 보존한다.

## 시간과 전환

| 종류 | 기존 동작 |
|---|---|
| 기본 포즈 | 대기6×.18초, 걷기8×.105초, 인사4×.18초, 점프5×.15초, 고개 숙이기8×.17초, 수줍음6×.19초, 생각6×.22초, 기울이기6×.19초 |
| 재생 반복 | 기존 렌더러는 상태가 유지되는 동안 modulo로 반복한다. 제스처의 기본 상태 길이는 프레임 수×간격이며 보통 한 번 후 전환한다. 새 팩은 loop/once/pingpong 메타데이터를 따른다. |
| 이동 | 리베르타 일반 걷기와 두 캐릭터의 테두리 걷기는 이동 거리/(신체높이×.4) 기준으로 발을 진행한다. 제니스 일반 걷기는 기존 시간 기반이다. |
| 대기·산책 | 대기 .8~2.4초, 일반 산책 최대15초, 테두리 걷기6~11초와 제자리 휴식을 번갈아 선택한다. 테두리 방향은 유지한다. |
| 시선 | atan2(dx,-dy)로 16방향을 선택한다. 가까운 커서가 있으면 일반 행동·걷기보다 우선하고 이탈 여유 거리를 둔다. 드래그·착지·코너는 끝까지 진행한다. |
| 배고픔 | 0스택·빵 주기 켜짐일 때 다음 행동 선택 경계에서 4×.45초. 처음6~10초, 이후12~20초 대기한다. |
| 드래그·낙하 | 매달림과 관성 회전, 중력 이동을 유지한다. 낙하 진행률 .16/.48/.84 경계로 매달림·접기·펴기·정자세를 선택한다. 캐릭터별 그림 방향 각도를 뺀다. |
| 착지 | .48초. .06초 전 공중, .28초 전 웅크림, 이후 일어서기. |
| 코너 | 테두리의 네 직선과 네 코너 중 코너를 .6초에 통과하며 4포즈와 몸체90도 회전을 적용한다. 시계 방향은 로컬 좌우 반전. |
| 빵 받기 | .65초. 진행률 .85 전 위 보기, 이후 받기. 떨어지는 빵은 진행률²로 이동한다. |
| 먹기·만족 | 1.6초 동안1·2번을 .22초마다 교대, 이후3번 .85초. 먹기 완료 전환 시 스택을 센다. |
| 거절 | 2.8초. 1.3초까지1·2번을 .22초마다 교대, 마지막3번은1.5초 유지한다. |

`advance` 우선순위는 소화/쿨다운 처리 후 메뉴 동결 → 먹기 → 드래그 → 낙하 → 착지 → 누른 상태 → 코너 → 근접 시선 → 일시정지 → 일반 행동이다. `update_frame`은 먹기 → 물리 → 테두리 → 일반 표시 순서다. 타이머33ms, 큰 dt 제한.1초를 유지한다. 물리·먹기의 의미 단계 타이밍을 일반 FPS 타이머로 바꾸지 않았다.

## 분리와 확인

캐릭터 ID·이름·이미지 참조·자르기·배율·방향 각도는 `characters/*/character.json`으로 이동했다. `desktop_pet.py`는 공통 리소스 인터페이스만 호출한다. 기존 그림은 `legacy-v1` 렌더러를 통해 같은 Qt 자르기·마스크·스케일 연산을 적용한다. 새 팩은 `manifest-v1` 공통 캔버스·배율·앵커를 사용한다.

`analyze`는 AST에서 상태 지정과 `enter_state` 호출을 추출하고 동적 선택은 카탈로그 바인딩과 대조한다. 알 수 없는 상태를 보고하므로 새 코드 행동의 카탈로그 누락을 검출할 수 있다. AST만으로 모든 실행 경로를 증명하지 않으므로 실제 게임 회귀 검증과 함께 사용한다. 새 Action ID의 제작 항목은 모든 캐릭터에 자동으로 나타난다.

제니스와 리베르타의 변경 전후 동일 시퀀스 936프레임은 픽셀 해시·창 크기·좌표·상태가 일치했고, 원본 PNG17개의 SHA-256도 같다. 별도의 Windows 창 버퍼 검사1,152프레임은 회전 잔상과 투명 영역 클릭 통과를 검증한다. 상세 결과는 [검증 보고서](regression-results.md)를 참조한다.
