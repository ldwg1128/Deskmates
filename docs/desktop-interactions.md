# 데스크톱 상호작용

`desktop_interactions.py`는 기존 산책·먹기·드래그 컨트롤러에 선택적 행동을 연결한다. `window_surfaces.py`는 일반 Windows 창의 위치·가시성만 읽는다. 다른 프로그램에 입력이나 창 이동 명령을 보내지 않는다. EnumWindows, DWM의 실제 표시 경계, 창 모니터와 Qt 배율을 이용하며, 최소화·닫힘·cloaking·자기 프로세스·도구 창을 제외한다. 제목 표시줄 스타일이 없는 특수 창은 대상에서 제외한다.

## 사용과 전환

| 동작 | 시작 | 종료 / 복귀 |
|---|---|---|
| 창 위에 앉기 | 드래그를 일반 창 상단 근처에서 놓기 | 2.2~3.8초 후 점프 → 낙하 → 착지 |
| 세로면 매달리기 | 드래그를 창 좌우 세로 가장자리 근처에서 놓기 | 같은 손 접촉점으로 4포즈 반복 → 낙하 → 착지 |
| 잠들기 | 캐릭터와 상호작용 없이 기본 30분 | 아래쪽 구석으로 이동 → 수면; 클릭·가까이 움직인 커서·우클릭으로 귀찮아하며 깨기 |
| 커서 잡기 | 일반 산책에서 허리 높이의 가까운 커서를 0.7초 유지 | 접근 → 잡기 → 원래 산책 중심 유지; 커서가 멀어지면 취소 |
| 공 차기 | 우클릭으로 공 꺼내기 후 발 근처에 끌어 놓기 | 접근 → 차기 → 공이 날아가며 사라짐; 공 치우기 가능 |
| 공에 머리 맞기 | 위에서 놓은 공이 머리를 아래 방향으로 통과 | 놀람 → 머리 감싸기 → 문지르기 → 회복; 공은 좌우 무작위로 튄 뒤 바닥에 정지 |
| 몰래 간식 | 배고픔 0스택이고 빵 주기가 켜진 상태에서 낮은 확률 | 주머니 간식 꺼내 먹기; 완료 시 1스택, 중단 시 추가 없음 |

오른쪽 창 가장자리는 **왼쪽을 바라보는 옆모습**, 왼쪽 가장자리는 반전한 옆모습이다. 몸은 창 바깥에 있고 손은 얼굴 높이에서 창의 세로면을 잡는다. 창 상단에 양손을 올려 거꾸로 매달리는 기존 드래그 그림과 구분한다. 창 위치·크기가 바뀌면 접촉점의 상대 위치를 따라간다. 다른 창에 가려진 접촉점이나 캐릭터가 화면 밖으로 잘릴 초기 위치에는 붙지 않는다. 창이 닫히거나 최소화되면 즉시 낙하한다.

기존 드래그·먹기·착지는 우선하며, 명시적인 캐릭터 변경·크기 변경·산책 방식 변경 시 추가 동작을 취소한다. 일시정지는 자동 접근·수면·간식을 멈추지만 직접 옮겨 놓은 창에서 뛰어내리거나 떨어지는 동작은 끝낸다. 제자리 모드에서는 수면 이동과 커서·공 접근을 생략한다. 테두리 산책의 수면 이동은 설정한 방향을 유지하며, 일반 산책의 커서·공 접근을 테두리에 적용하지 않는다. 공은 별도 창으로 끌 수 있고 기존 캐릭터/산책 설정을 바꾸지 않는다. 커서 잡기는 시각적 반응이며 시스템 커서를 붙잡거나 이동시키지 않는다.

방치 시간은 전역 키보드 사용 시간이 아니라 캐릭터와의 상호작용을 기준으로 센다. 가까이에서 커서를 움직이거나 캐릭터·공을 만지거나 캐릭터 우클릭 메뉴·행동 설정을 열면 초기화한다. 잠들기 대기는 5/10/30분 중 선택하고 기본값은 사용자 요청인 **30분**이다. 설정은 기존 JSON에 `window_interactions`, `sleep_enabled`, `sleep_seconds`, `cursor_play_enabled`, `rare_actions_enabled`를 추가한다. 키가 없는 기존 설정도 읽으며 임시 수면·매달리기 상태와 공 위치는 다음 실행에 복원하지 않는다.

희귀 간식은 첫 검사까지 5~10분, 이후 배고플 때 1분 간격으로 5% 확률을 검사한다. 한 번 먹으면 15~30분의 별도 대기를 둔다. 기존 게임 난수 생성기와 분리해 기존 일반 행동의 선택 순서에 영향을 주지 않는다.

## 리소스와 확장

공통 카탈로그에 `window_sit`, `ledge_struggle`, `sleep`, `wake_annoyed`, `cursor_grab`, `kick`, `secret_snack` 7개 선택 행동을 추가했다. 전체 22개 리소스 / 32개 상태 바인딩이다. 새 캐릭터에는 기존 제작 CLI의 체크리스트·프롬프트·템플릿·누락 검사에 자동 반영된다. 파일이 없으면 각 행동의 fallback을 사용한다. 기존 기본 행동의 이미지·배율·재생 코드는 유지했다.

`characters/{zenith,liberta}/animations/`에 새 4프레임 스트립을 연결했다. 셀은 256×320이며 동일 행동 안에서는 공통 배율을 사용한다. `anchor`는 일반 몸체 기준, `support_anchor`는 창에 닿는 손/앉은 위치다. 접촉점은 캐릭터 JSON으로 재정의할 수 있고 새 제작 셀 크기에는 카탈로그의 기본 접촉점을 비례 적용한다. 창 접촉점은 가이드에 녹색 표시하고 생성 프롬프트와 가져온 메타데이터에도 포함한다. 일반 애니메이션 캔버스에 이 포즈들을 합치지 않아 기존 화면상 크기를 바꾸지 않는다.

그림은 **내장 image_gen 도구**로 기존 캐릭터의 대기 프레임을 참조해 생성했다. 원본은 `.codex/generated_images`에 남기고 프로젝트의 `characters/{id}/sources/`에도 보관했다. 기존 `assets/*.png`는 수정하지 않았다. 사용한 제작 요구와 최종 옆모습 프롬프트는 [이미지 프롬프트](desktop-interaction-prompts.md)에 기록했다. 최초 정면 매달림은 참고 원본에 보관하고 실행 시에는 `ledge-struggle-side-v2.png`만 사용한다. 셀 배치와 자르기·공통 배율·접촉점은 `sources/*layout*.json`에서 확인할 수 있다. `tools/prepare_side_cling.py`로 최종 옆모습 시트를 다시 포장할 수 있다.

## 검증

`python verify_desktop_interactions.py`는 두 캐릭터, 양쪽 세로면의 옆모습/접촉점, 창 이동·닫힘·최소화, 점프·착지 후 양쪽 산책 방식 복귀, 30분 수면·클릭 깨우기, 제자리·테두리 수면, 커서 접근·이탈·재시도 간격, 별도 공 드래그·차기, 간식 1회 계수·취소, 설정 저장·취소·복원, 64/400px에서 포즈 잘림과 실제 Windows 창 버퍼 픽셀 일치를 검사한다. 시간은 주입해 실제30분을 기다리지 않는다. `artifacts/interactions/all-interactions-preview.png`에 게임 렌더링 미리보기를 출력한다. 최종 매달림 GIF는 `artifacts/interactions/{zenith,liberta}/ledge_struggle.gif`에 있다.

전체 회귀 검사는 `python verify_all.py`로 실행한다. Windows API와 테스트용 창을 이용한 실제 가시성 검사도 포함하며 사용자의 다른 프로그램을 조작하지 않는다. 수동 사용감과 생성 그림의 미세한 외형 차이는 자동 테스트로 보장되지 않는다.
