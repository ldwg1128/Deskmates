# 캐릭터 파이프라인 검증 결과

검증일: 2026-10-15. Windows 11 (26200), Python 3.14.5, PySide6/Qt 6.11.2, PyInstaller 6.22.2.

## 창 상단 앉기 판정 개선

변경 후 `python verify_all.py`의15개 검사가 모두 종료 코드0으로 통과했다. 전체 결과는 `artifacts/resource-refactor/regression-results.json`에 저장했다.

상단 허용 범위를 `max(28px, 캐릭터 높이 × 0.24)`로 넓혔다(기본160px에서 ±38.4px). 드래그의 마지막 이동 좌표 대신 버튼을 놓은 실제 좌표로 판정하며, 화면 밖으로 몸이 잘려 붙기를 거절한 경우 드래그 상태와 위치를 보존해 정상 낙하 또는 테두리 산책으로 복귀한다.

`verify_window_perching.py`는3캐릭터 × 3크기 × 2산책 방식 × 상단 위/아래의36번 놓기를 검사한다. 앉기→점프→낙하→기존 산책 복귀, 오래된 이동 좌표의 오판정, 실패 시 상태 복원, 가려진 창 제외, 세로면 매달리기, 실제 DWM 창 좌표로 앉기까지 통과했다. 화면 최상단에 붙은 창처럼 캐릭터가 온전히 앉을 공간이 없는 경우는 계속 제외한다.

검증한 실행파일은 `dist/DeskMates.exe`에 반영했다. 실행파일만 임시 폴더로 복사해 제니스·리베르타·세이르의 시작/종료를 확인했다(모두 종료 코드0, 오류 로그 없음). 실행파일 검사 기록은 `artifacts/window-perching/exe-smoke.json`에 저장한다.

## 최신 제니스 선명도 개선 검증

2026-10-15의 표시 품질 개선 후 `verify_all.py`14개 검사를 모두 통과했다. 원본 렌더러를 선택한936프레임은 기존 픽셀 기준과 완전히 같고, 보정을 켠936프레임은 좌표·상태·캔버스를 유지한다. 제니스512개 스프라이트의 알파 포함 영역·발 기준·클릭 마스크를 비교했으며 PNG17개 원본 해시는 그대로다. Pillow12.3.0이 보정에 사용되며 단일 EXE에도 포함된다.

현재 `dist/DeskMates.exe`는96,553,259bytes다. EXE만 복사한 빈 폴더에서 제니스400px·리베르타160px·세이르160px의 정상 실행과 설정 저장·종료(모두 코드0, 경고 로그 없음)를 확인했다. [전후 비교와 구현·검증 설명](zenith-clarity.md), `artifacts/zenith-clarity/results.json`, `artifacts/zenith-clarity/exe-smoke.json`을 참고한다. 아래 내용은 이전 파이프라인 구축 단계의 기록이다.

## 원본 보존

변경 전 `d892590`의 화면을 기록한 `tests/fixtures/render-baseline.json`과 변경 후를 비교했다. 제니스·리베르타 각각 64/160/320/400px에서 일반 행동·먹기·배고픔·거절·시선·드래그·낙하·양방향 테두리의 모든 구간을 같은 시퀀스로 재생했다. **936프레임의 RGBA 해시, 창 크기, 좌표, 상태가 일치**했다. **기존 PNG17개 바이트/SHA-256도 모두 같다.** 픽셀 기준은 위 Qt/Windows 환경이며 다른 Qt 버전의 래스터화 차이는 별도 확인해야 한다.

## 더미와 산출물

`examples/characters/dummy`는 실제 등록 가능한 독립 팩이다. idle7프레임/pingpong·걷기10프레임으로 고정 프레임 규격에 의존하지 않음을 검증했다. 테스트는 핵심 게임 코드 파일의 해시를 전후 비교해 바꾸지 않았음을 확인한다.

`python examples/demo_autogen.py`는 `artifacts/autogen-demo/characters/auto_dummy`를 등록한다. 최초 전체 스트립 생성 후 비어 있는 걷기2번만 재생성하고 다른 슬롯을 바꾸려는 모델의 결과를 차단했다. 초기15개 행동을 모두 통과해 등록했으며 결과 JSON·검토 HTML·GIF를 보존한다. 현재 자동 테스트는 추가 행동까지 포함한22개 카탈로그로 실행한다. 이 모델은 기하 도형으로 만든 결정론적 테스트 모델이며 실제 그림 생성 서비스가 아니다.

OpenAI 어댑터는 다중 참고 이미지·투명 PNG 요청·선택적 수정 마스크·비전 응답·낮은 확신의 검토 전환을 **모의 SDK**로 검증했다. SDK/API 연결이 없는 경우 명세·프롬프트만 출력한다. 실제 유료 API 호출과 실제 서비스의 이미지 품질 검증은 수행하지 않았다. 자동 통계·비전 검사는 외형 동일성을 보장하지 않으며 검토 경로를 남긴다. 비용 제한은 보수적 요청당 예약액 기준이고 서비스 청구 한도는 서비스에서 별도 설정한다.

## 실행파일

실행 중인 `dist/DeskMates.exe`의 Windows 파일 잠금으로 그 파일에 덮어쓰는 빌드는 실패했다. 앱을 종료하지 않고 `build.ps1 -OutputDirectory artifacts/resource-refactor/release`로 새 **단일 EXE 빌드에 성공**했다. Pillow/NumPy/이미지 생성 SDK는 게임에 필요하지 않으므로 개발 도구와 분리했다.

새 EXE에서 제니스, 외부 더미, 자동 생성 더미를 각각 별도 설정 파일로 시작해 캐릭터 발견·설정 저장·정상 종료(각 코드0)를 확인했다. 결과는 `artifacts/resource-refactor/frozen-results.json`에 남겼다. 기존 사용자 앱과 설정은 이 검사에 사용하지 않았다.

이전 창·수면·놀이 및 옆모습 매달림 단계의 단일 EXE는 `artifacts/desktop-interactions/DeskMates.exe`에 별도 빌드했다. 두 기본 캐릭터의 새 이미지 로딩·기본30분 수면·추가 행동 설정 저장·정상 종료를 독립 설정으로 검사했으며 결과는 `artifacts/interactions/frozen-results.json`에 저장했다. 추가 포즈 그림은 내장 이미지 생성 도구로 제작했고 생성 원본·프롬프트·좌표는 [제작 기록](desktop-interaction-prompts.md)에 보존했다. 기존 원본17개와936프레임 비교도 다시 통과했다.

세이르를 포함한 최종 배포 파일은 사용자 요청에 따라 **`dist/DeskMates.exe`**로 빌드했다. 원본·템플릿의 중복 포함을 줄여 캐릭터 런타임39개 파일(약16MB)을 묶었다. EXE는88,616,146바이트다. 빈 폴더에 EXE만 복사한 상태에서 세이르·리베르타·제니스의 이미지 로딩, 설정 저장과 정상 종료(모두 코드0·오류 로그 없음)를 확인했다. EXE 해시·크기와 종료 코드는 `artifacts/seir/frozen-results.json`에 저장했다. [세이르 제작 기록](seir-character.md)과22개/110프레임의 제작 명세도 함께 제공한다.
